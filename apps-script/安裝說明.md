# Apps Script 安裝說明：把報名資料同步到 Google 試算表

這支腳本會把 Firebase 裡的會員、會員申請、每場報名，整理寫進「鹿角包場計劃」試算表的三個新分頁：

| 分頁 | 內容 |
|---|---|
| 系統_會員名單 | 每位會員／申請中的人：時段、場地、方案 |
| 系統_報名明細 | 每一筆報名：日期、場地、報名人、朋友、DUPR、付款方式與狀態、正取／候補、簽到 |
| 系統_每場統計 | 每場每面場：會員數、請假、單次正取人數、候補、出席、簽到、應收／已收金額 |

- 腳本**只讀** Firebase，不會改動報名資料
- 這三個分頁每次同步都會整頁覆蓋，**不要在裡面手動輸入**；要做計算，請在其他分頁用公式引用它們
- 你原本的分頁（營運總覽、2027場次行事曆、每場收支紀錄…）完全不會被動到

## 安裝步驟（只要做一次）

1. 先到 Firebase 後台發布最新的資料庫規則（[firebase-rules-chains.json](../firebase-rules-chains.json) 的 `pkclub`、`chains` 兩段），再用電腦打開「鹿角包場計劃」試算表
2. 上方選單 **擴充功能 → Apps Script**
3. 左邊齒輪 **專案設定** → 勾選「**在編輯器中顯示 appsscript.json 資訊清單檔案**」
4. 回到左邊 **編輯器**（`< >` 圖示）：
   - 點 `appsscript.json`，整份換成本資料夾的 [appsscript.json](appsscript.json) 內容
   - 點 `程式碼.gs`，整份換成 [同步報名資料.gs](同步報名資料.gs) 內容
   - 按上方 💾 儲存
5. 上方函式下拉選單選 `syncAll` → 按 **▶ 執行**
   - 第一次會跳「需要授權」→ 選你的帳號 → 若出現「Google 尚未驗證這個應用程式」，按「進階」→「前往（不安全）」→ 允許
   - 這是你自己寫的腳本，授權的是讓它讀你的 Firebase 和寫這份試算表
6. 回到試算表，應該會看到三個「系統_」分頁出現
7. 重新整理試算表，上方會多一個選單 **進擊的匹克團**：
   - **立即同步報名資料**：馬上更新一次
   - **開啟自動同步（每 10 分鐘）**：之後每 10 分鐘自動更新（關掉試算表也會跑）
   - **停止自動同步**

## 常見問題

**讀取權限怎麼運作？**
腳本會先試目前 Google 帳號的 Firebase 權限；被拒絕（HTTP 401）就自動改用公開讀取。
公開讀取需要資料庫規則裡 `chains` 有 `".read": true`（見 [firebase-rules-chains.json](../firebase-rules-chains.json)），
所以規則更新後一定要到 Firebase 後台貼上並按「發布」。寫入權限不受影響。
（Firebase 的「資料庫密鑰」已被 Google 淘汰，新專案沒有密鑰可用，不需要設定 FIREBASE_SECRET。）

**執行時出現「讀取 Firebase「chains」失敗（HTTP 401）」**
代表最新的資料庫規則還沒發布，照上面說明發布後再執行一次。

**日期欄怎麼來的？**
接龍只存「1/3（日）」這樣的文字，腳本依開團時間推算年份（例如 11 月開 1 月的團會算成隔年）。

**改了網站程式後要不要改這支腳本？**
名額計算（會員保留、正取／候補）跟網站 [index.js](../index.js) 的 `courtData()` 是同一套邏輯；如果之後改了名額規則，兩邊要一起改。
